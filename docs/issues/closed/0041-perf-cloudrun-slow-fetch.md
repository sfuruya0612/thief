# Cloud Run のデータ取得が遅い原因を特定して改善する

Created: 2026-07-18
Completed: 2026-07-18
Model: Claude Opus 4.8

## 背景

Cloud Run のリソース取得に約 50 秒かかる。
`internal/gcp/cloudrun.go` の `ListCloudRun` は、サービスとジョブを次のように取得している。

- サービスは `projects/{projectID}/locations/-` のワイルドカードで `ListServices` を 1 回呼び出し、全ロケーションを一括取得する。
- ジョブは Jobs API が Parent のワイルドカードを受け付けないため、`listRunLocations` でロケーション一覧を取得し、ロケーションごとに `ListJobs` を逐次呼び出す。

ロケーションごとの `ListJobs` を逐次実行しているため、ロケーション数に比例して所要時間が伸びると考えられる。
ただし 50 秒の主因がこの逐次処理なのか、`listRunLocations` なのか、個々の API 応答自体が遅いのかは未計測であり、まず原因を特定する必要がある。
なお `handleGCPCloudRun` は `serveCached` を通しており、`cacheTTL` は 1 時間 (`internal/api/server.go`) であるため、遅延が表面化するのはキャッシュミス時のみである。

## 目的

Cloud Run のデータ取得が遅い原因を計測に基づいて特定する。
特定した原因に応じて改善を行うかどうかは、設計上の論点で判断する。

## 対応内容

### 調査

- サービス取得、`listRunLocations`、ロケーションごとの `ListJobs` の各所要時間を計測する
- 逐次処理と個々の API 応答のどちらが支配的かを切り分ける

### backend (改善を行う場合)

- 原因がロケーションごとの `ListJobs` の逐次実行であれば、これを並列化する (`golang.org/x/sync/errgroup` を用い、キャンセルとエラー伝播を揃え、goroutine の終了経路を確保する)
- サービス取得・ロケーション取得・ジョブ取得の同時実行が有効かを検討する

## 設計上の論点

- 本 issue の元になった TODO は「なぜ遅いのか」という原因調査の依頼である。改善まで本 issue で行うか、原因特定のみで閉じて改善を別 issue に分けるかを決める必要がある。
- 改善を行う場合、目標とする取得時間を定める必要がある。原因が GCP 側 API のロケーション単位のレイテンシなど並列化で縮まらない要因であれば、短縮できない可能性がある。この場合は「短縮」を完了条件にできないため、目標値または「有意な短縮 (before / after を明記)」として定量化する。

## 完了条件

- 遅延の原因が計測に基づいて特定され、記録されている
- (改善を行う場合) 改善が入り、設計上の論点で定めた目標に対する before / after が記録されている

## 解決方法

本作業環境には実 GCP プロジェクトへの認証情報がなく、`ListCloudRun` を実際に呼び出して
50 秒遅延を実測することができない。設計上の論点の「原因特定のみで閉じて改善を別 issue に
分けるか」は分ける方針とした (ユーザ判断)。本 issue は計測手段の追加までとし、改善は
docs/issues/0043 (別 issue) に分離した。

### backend

- `internal/gcp/cloudrun.go` の `ListCloudRun` に `log/slog` での区間計測を追加した。
  - サービス一覧取得 (`ListServices`) の所要時間・件数
  - `listRunLocations` の所要時間・件数
  - ロケーションごとの `ListJobs` の所要時間・件数 (ロケーション単位、および全ロケーション
    合計)
  - 全体の所要時間・件数
- 逐次処理 (ロケーションごとの `ListJobs`) と個々の API 応答のどちらが支配的かを、実環境の
  ログから切り分けられるようにした。

### 完了条件の確認

- 「遅延の原因が計測に基づいて特定され、記録されている」は、本環境では実測できないため
  未達成。ログ出力の追加までを完了条件の代替とし、実環境での計測・原因特定は docs/issues/0043 で
  ユーザが行う。
- 改善 (並列化) は本 issue のスコープ外とし、計測結果が出た後に docs/issues/0043 で対応する。
