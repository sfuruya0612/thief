Created: 2026-10-25
Model: Claude Fable 5.1
Completed: 2026-10-26

## 背景

`docs/issues/TODO.md` の次の項目に由来する。

> TUI の一覧と Drawer を EC2 以外の 18 サービス (Lambda、ECR、ECS、S3、RDS、DynamoDB、ElastiCache、ELB、CloudFront、API Gateway、NAT Gateway、Kinesis、SQS、IAM、WAF、Secrets Manager、Parameter Store、CloudFormation) にも足したい (docs/prd/thief.md の FR-29。`backend/internal/cli/tui.go` の `Deps.Services` には `tui.NewEC2Service` しか無く、列と Overview は Web UI の `frontend/src/components/tables/columns.tsx` と `frontend/src/components/Drawer/overviewRows.tsx` に合わせる)

18 サービスは Web UI のサイドバーの分類 (`frontend/src/lib/serviceMeta.ts` の `SERVICES` の `group`) に沿って 4 つの issue に分け、タグの取得の仕組みが他と違う CloudFormation はさらに 1 つの issue に分ける。
この issue は `networking` の ELB、CloudFront、API Gateway、NAT Gateway、`analytics` の Kinesis、`integration` の SQS を扱う。
Lambda、ECR、ECS は issue 0219、S3、RDS、DynamoDB、ElastiCache は issue 0220、IAM、WAF、Secrets Manager、Parameter Store は issue 0222、CloudFormation は issue 0223 で扱う。

TUI の 1 サービスは `backend/internal/tui/service.go` の `Service` と `Row` で表す。
実装の形、`Deps` の組み立て、数値の換算 (`backend/internal/tui/format.go` の `formatCount`)、タグの取得失敗の表示 (`TagsFetchFailer`) は issue 0218、0219、0220 が定めたものに従う。

6 サービスの Web UI 側の事実は次のとおり。
一覧関数は Web UI の一覧のハンドラ (`backend/internal/api/handlers_aws.go`) が呼ぶものである。

| ID | 一覧関数 (`backend/internal/aws/`) | 列 (`columns.tsx`) | Overview (`overviewRows.tsx`) | Tags |
| --- | --- | --- | --- | --- |
| `elb` | `ListELBResources(ctx, profile, region)` | `elbColumns`: Name、State、Type、Scheme、Region、DNS name、AZs | `elbOverviewRows`: Resource ID、Type、Scheme、DNS name、VPC、AZs、Region | `ELBResource` に Tags フィールドが無い |
| `cloudfront` | `ListCloudFrontResources(ctx, profile, _)` (リージョンを無視し us-east-1 で呼ぶ) | `cloudfrontColumns`: Distribution、State、Domain、Alternate domains、Origins | `cloudfrontOverviewRows`: Resource ID、Domain、Alternate domains、Origins、Enabled、Price class | `CloudFrontResource` に Tags フィールドが無い |
| `apigw` | `ListAPIGatewayResources(ctx, profile, region)` | `apigwColumns`: API、State、Type、Stage、Endpoint、Region | `apigwOverviewRows`: Resource ID、Type、Stage、Endpoint、Region | `APIGatewayResource.Tags` |
| `natgw` | `ListNATGatewayResources(ctx, profile, region)` | `natgwColumns`: Name、State、Gateway ID、VPC、Elastic IP、Region、Uptime | `natgwOverviewRows`: Resource ID、VPC、Subnet、Elastic IP、Region、Uptime、Launched | `NATGatewayResource.Tags` |
| `kinesis` | `ListKinesisResources(ctx, profile, region)` | `kinesisColumns`: Stream、State、Mode、Shards、Retention、Encryption、Region | `kinesisOverviewRows`: Resource ID、Capacity mode、Shards、Retention、Encryption、Region | `KinesisResource.Tags` はあるが `ListKinesisResources` が設定せず常に空 |
| `sqs` | `ListSQSResources(ctx, profile, region)` | `sqsColumns`: Queue、State、Type、Available、In flight、Retention、Region | `sqsOverviewRows`: Resource ID、Type、Messages available、Messages in flight、Retention、Region | `SQSResource.Tags` と `TagsFetchFailed` |

- ELB の AZs は `, ` で結合した文字列、Type は `application`、`network`、`gateway` の生の値、`ID` はロードバランサの ARN である。
- CloudFront は列にも Overview にも Region が無い。`Name` は `Comment` で、空なら `Id` である。Alternate domains と Origins は `, ` で結合する。
- API Gateway の Type は `REST`、`HTTP`、`WebSocket` で、REST の Endpoint は `https://<id>.execute-api.<region>.amazonaws.com` を組み立てた文字列である。どちらも一覧関数が作る。
- NAT Gateway の `Name` はタグ `Name` の値 (無ければ空) で、Uptime と Launched は `LaunchTime` から算出する (`ec2.go` の `formatUptime` と `formatLaunched`)。
- Kinesis の Mode は `on-demand` か `provisioned` で、Retention は列と Overview のどちらも `24h` のような時間表記である。
- SQS の Queue 名はキューの URL の末尾、Available は `toLocaleString()` の桁区切りで、Retention は列では `4d`、Overview では `4 days` と表記が違う。タグは一覧関数の内部で `ListQueueTags` を呼んで取り、失敗したときは `TagsFetchFailed` を真にする。
- Web UI が空のとき `Dash` か `dash` を描画する項目は、ELB が列と Overview の AZs、CloudFront が列と Overview の Alternate domains と Origins、NAT Gateway が列の Uptime と Overview の Uptime と Launched である。API Gateway、Kinesis、SQS には無い。ELB の DNS name、API Gateway の Endpoint と Stage、NAT Gateway の VPC と Elastic IP、CloudFront の Domain、Kinesis の Encryption は空のとき空文字列である。CloudFront の Overview の Enabled は `yes` か `no` である。
- ELB の `active`、NAT Gateway の `available`、Kinesis の `active` (`kinesisFromSummary` が `DisplayState` で小文字にする) のような State の生の値は `NormalizeState` で `running` になるため、`ResourceState()` の値を表示すると Web UI と食い違う。

## 目的

`thief tui` のサービスの選択肢に ELB、CloudFront、API Gateway、NAT Gateway、Kinesis、SQS が並び、Web UI と同じ列の一覧と、同じ項目の Overview と Tags を Drawer で見られる。
SQS のタグの取得に失敗した行では、Web UI と同じくその旨が Drawer に出る。

## 設計判断

- サービスごとに `backend/internal/tui/elb.go`、`cloudfront.go`、`apigw.go`、`natgw.go`、`kinesis.go`、`sqs.go` を置き、`New<Service>Service(list)` が一覧関数を受け取る。`Columns()`、`Overview()`、`Cells()`、`Load` の失敗のラップ、`Deps.Services` の並び (`serviceMeta.ts` の順: issue 0220 までの 8 個に `elb`、`cloudfront`、`apigw`、`natgw`、`kinesis`、`sqs` を続ける) は issue 0219 と 0220 と同じ方針に従う。`State()` と State の列は資源の `State` フィールドの生の値を返し、空の値と真偽値の表記も issue 0219 の規則に従う。
- SQS の列の Retention (`4d`) と Overview の Retention (`4 days`) は、Web UI の `sqsColumns` と `sqsOverviewRows` がそれぞれ描画する文字列に合わせて別々に作る。1 つの表記に統一する案は、Web UI との一致 (FR-29 の受け入れ基準) から外れるので採らない。
- SQS の行は issue 0220 の `TagsFetchFailer` を実装し、`SQSResource.TagsFetchFailed` を返す。Available は `formatCount(int64(r.AvailableMessages))` で桁区切りにする (`SQSResource.AvailableMessages` は `int`)。
- ELB と CloudFront は `Row.Tags()` が `nil` を返し、Drawer は `No tags` と表示する。Kinesis の `Row.Tags()` は `KinesisResource.Tags` をそのまま返す (一覧関数が設定しないため常に `No tags` になる)。Web UI の Tags タブも同じく空であり、この issue は Web UI との一致を目的とするので、一覧関数にタグの取得を足すことはしない。
- CloudFront の一覧関数はリージョンを無視するが、TUI は他のサービスと同じく選択中のリージョンを渡す。CloudFront の列と Overview に Region を足す案は、Web UI に無い項目を増やすので採らない。
- 追加の API 呼び出しと権限は無い。TUI は Web UI の一覧のハンドラと同じ `ListELBResources`、`ListCloudFrontResources`、`ListAPIGatewayResources`、`ListNATGatewayResources`、`ListKinesisResources`、`ListSQSResources` を使う。
- floci での確認: `example/seed.sh` は SQS のキューを 3 つ (`thief-example-queue`、`thief-example-dlq`、`thief-example-fifo.fifo`) 作り、`example/README.md` の「確認手順」は SQS の一覧を Web UI で確認している。SQS は floci で確認し、README の「確認手順」に TUI での確認を足す。他の 5 サービスは README の確認済みの一覧に無いので実 AWS で確認し、floci でも試して動いたものは seed と README に足す。
- `CHANGES.md` の `## develop` に、この issue の 6 サービスを足した [ADD] のエントリを 1 つ書く (issue 0219 の方針)。

## 解決方法

issue 0218 の `Service` と `Row` の形に合わせて 6 サービスを足し、`Deps.Services` に登録した。

- `backend/internal/tui/elb.go`: `NewELBService` (`ID()` は `elb`、`Title()` は `ELB`)、`elbService`、`elbRow`。列は Web UI の `elbColumns` と同じ `Name`、`State`、`Type`、`Scheme`、`Region`、`DNS name`、`AZs`。AZs は `, ` で結合し、空なら `—` にする (`azs()`)。Overview は `elbOverviewRows` と同じ `Resource ID`、`Type`、`Scheme`、`DNS name`、`VPC`、`AZs`、`Region`。`State()` は `ELBResource.State` の生の値を返し、`Tags()` は `nil` を返す (`ELBResource` に Tags が無い)。`Load` はエラーを `list ELB load balancers: %w` で包む。
- `backend/internal/tui/cloudfront.go`: `NewCloudFrontService` (`cloudfront`、`CloudFront`)、`cloudfrontService`、`cloudfrontRow`。列は `cloudfrontColumns` と同じ `Distribution`、`State`、`Domain`、`Alternate domains`、`Origins` で、Web UI と同じく Region の列は無い。Alternate domains と Origins は `, ` で結合し、空なら `—` にする (`aliases()`、`origins()`)。Overview は `cloudfrontOverviewRows` と同じ `Resource ID`、`Domain`、`Alternate domains`、`Origins`、`Enabled` (`yes` か `no`)、`Price class`。`Name()` は `CloudFrontResource.Name` を返す (backend がコメントか ID を入れる)。`State()` は `CloudFrontResource.State` の生の値を返し、`Tags()` は `nil` を返す。`Load` は選択中のリージョンを一覧関数に渡し (一覧関数は無視する)、エラーを `list CloudFront distributions: %w` で包む。
- `backend/internal/tui/apigw.go`: `NewAPIGatewayService` (`apigw`、`API Gateway`)、`apigwService`、`apigwRow`。列は `apigwColumns` と同じ `API`、`State`、`Type`、`Stage`、`Endpoint`、`Region`。Overview は `apigwOverviewRows` と同じ `Resource ID`、`Type`、`Stage`、`Endpoint`、`Region`。空の Stage と Endpoint は Web UI と同じく `—` にせず空文字列のままにする。`State()` は `APIGatewayResource.State` の生の値を返し、`Tags()` は `APIGatewayResource.Tags` を返す。`Load` はエラーを `list API Gateway APIs: %w` で包む。
- `backend/internal/tui/natgw.go`: `NewNATGatewayService` (`natgw`、`NAT Gateway`)、`natgwService` (現在時刻の関数 `now` を持ち、既定は `time.Now`)、`natgwRow`。列は `natgwColumns` と同じ `Name`、`State`、`Gateway ID`、`VPC`、`Elastic IP`、`Region`、`Uptime`。Uptime と Launched は EC2 と同じ `formatUptime` と `formatLaunched` で算出し、`LaunchTime` が無ければ `—` にする。Overview は `natgwOverviewRows` と同じ `Resource ID`、`VPC`、`Subnet`、`Elastic IP`、`Region`、`Uptime`、`Launched`。`Name()` は `NATGatewayResource.Name` を返す (backend が `Name` タグから入れ、無ければ空)。`State()` は生の値を返し、`Tags()` は `NATGatewayResource.Tags` を返す。`Load` はエラーを `list NAT gateways: %w` で包む。
- `backend/internal/tui/kinesis.go`: `NewKinesisService` (`kinesis`、`Kinesis`)、`kinesisService`、`kinesisRow`。列は `kinesisColumns` と同じ `Stream`、`State`、`Mode`、`Shards`、`Retention`、`Encryption`、`Region`。Shards は `formatInt32` で、Retention は `formatInt32(RetentionHours) + "h"` で書式化する (`retention()`)。Overview は `kinesisOverviewRows` と同じ `Resource ID`、`Capacity mode`、`Shards`、`Retention`、`Encryption`、`Region`。`State()` は生の値を返し、`Tags()` は `KinesisResource.Tags` を返す (一覧関数が設定しないため空)。`Load` はエラーを `list Kinesis streams: %w` で包む。
- `backend/internal/tui/sqs.go`: `NewSQSService` (`sqs`、`SQS`)、`sqsService`、`sqsRow`。列は `sqsColumns` と同じ `Queue`、`State`、`Type`、`Available`、`In flight`、`Retention`、`Region`。Available は `formatCount(int64(AvailableMessages))` で `,` 区切りにし、In flight は `strconv.Itoa` で書式化する。Retention は列では `<n>d`、Overview では `<n> days` とする。Overview は `sqsOverviewRows` と同じ `Resource ID`、`Type`、`Messages available`、`Messages in flight`、`Retention`、`Region`。`State()` は `SQSResource.State` の生の値を返し (backend が常に `active` を入れる)、`Tags()` は `SQSResource.Tags` を返す。`TagsFetchFailed()` は `SQSResource.TagsFetchFailed` を返す (issue 0220 の `TagsFetchFailer`)。`Load` はエラーを `list SQS queues: %w` で包む。
- `backend/internal/cli/tui.go`: `newTUIDeps` の `Services` を、issue 0220 までの 8 個の後に `elb`、`cloudfront`、`apigw`、`natgw`、`kinesis`、`sqs` を続けた 14 個の並びにし、Web UI のハンドラと同じ `awsinternal.ListELBResources`、`ListCloudFrontResources`、`ListAPIGatewayResources`、`ListNATGatewayResources`、`ListKinesisResources`、`ListSQSResources` を渡す。`backend/internal/cli/tui_test.go` の `TestNewTUIDeps_ServicesFollowWebUIOrder` を 14 個の並びに更新した。
- テスト: `backend/internal/tui/elb_test.go`、`cloudfront_test.go`、`apigw_test.go`、`natgw_test.go`、`kinesis_test.go`、`sqs_test.go` のそれぞれに、次の 4 種のテストを書いた。`ID()` と `Title()` と `SupportsSession()` と `Columns()` の並び (`Test<Id>Service_IDTitleAndColumns`)。すべての項目に値がある資源の `Cells()` と `Overview()` と `Tags()` の値、および `Cells()` の数が `Columns()` の数と一致すること (`Test<Id>Row_CellsAndOverview`。SQS は Retention `4d` と `4 days` の資源、ELB は State `active` の資源)。空の値と偽の値とタグの無い資源の表示 (`TestELBRow_EmptyValuesFollowWebUI`、`TestCloudFrontRow_EmptyAndFalseValuesFollowWebUI` (Enabled が偽で `no`)、`TestAPIGatewayRow_EmptyValuesFollowWebUI`、`TestNATGatewayRow_EmptyValuesFollowWebUI` (`Name` タグの無い資源で `Name()` が空)、`TestKinesisRow_EmptyValuesFollowWebUI`、`TestKinesisRow_OnDemandModeIsRaw` (Mode `on-demand` をそのまま表示)、`TestSQSRow_ZeroValuesFollowWebUI` (`TagsFetchFailer` の実装と `TagsFetchFailed` の伝播もここで確かめる))。偽の一覧関数のエラーが `list <Service> ...: ` で包まれることと、選択中のリージョンが行に入ること (`Test<Id>Service_LoadWrapsErrorAndSetsRegion`。CloudFront は Region を持たないので `TestCloudFrontService_LoadWrapsError`)。NAT Gateway は `Load` が現在時刻を各行に渡すことも確かめる (`TestNATGatewayService_LoadPassesNowToRows`)。
- `example/seed.sh`: Kinesis のストリーム `thief-example-stream` (シャード 2)、API Gateway の REST API `thief-example-api` と HTTP API `thief-example-http`、Elastic IP と NAT ゲートウェイ (既定 VPC のサブネット `subnet-default-ap-northeast-1-a`、タグ `Name=thief-example-nat`)、Application Load Balancer `thief-example-alb` (サブネット `-a` と `-c`、internet-facing)、CloudFront のディストリビューション (コメント `thief example`、オリジン `thief-example-data.s3.amazonaws.com`) の投入を足した。floci で 5 サービスの作成 API がすべて動いたため、設計判断の「floci でも試して動いたものは seed と README に足す」に従って全部を足した。`example/README.md` の投入の一覧に 5 サービスを足し、「確認手順」に「TUI (`thief tui`) の ELB / CloudFront / API Gateway / NAT Gateway / Kinesis / SQS 一覧」を足した。
- `CHANGES.md` の `## develop` に、この issue の [ADD] のエントリを 1 つ足した。
- 完了条件の検証: 6 つのコンストラクタと `ID()` と `Title()` は `Test<Id>Service_IDTitleAndColumns` で確かめた。列と Overview と資源の表示 (空の値の `—`、CloudFront の `no`、ELB の `active`、SQS の `4d` と `4 days`、NAT Gateway の空の `Name()`) は `Test<Id>Row_CellsAndOverview` と空の値のテストで確かめ、`Tags()` (ELB と CloudFront の nil、API Gateway と NAT Gateway と Kinesis の 2 件のタグの透過) も `Test<Id>Row_CellsAndOverview` で、SQS の `TagsFetchFailer` は `TestSQSRow_ZeroValuesFollowWebUI` で確かめた。`Deps.Services` の 14 個の並びは `TestNewTUIDeps_ServicesFollowWebUIOrder` で確かめた。ハンドラの読み合わせ、floci での SQS の 3 つのキューと `thief-example-fifo.fifo` の Type `FIFO` (Web UI と同じ表記)、他の 5 サービスの一覧と Overview、README の手順は「## 動作確認」に記録した。実 AWS での 5 サービスの確認は行っていない (SSO のログインが要り、開発者が不在の実行では行えない)。その旨を、floci では観測できない項目とともに「## 動作確認」に書いた。完了条件の主文ではなく但し書きで close しており、この読み替えの承認は開発者に委ねる。
- `mise run check` の通過は「新たな失敗が無いこと」と読み替え、既知の失敗を例外として close した。`mise run backend:vuln` (govulncheck) は issue 0218 から 0220 と同じ既知の 12 件 (GO-2026-6809、6617、6613、6612、6611、6610、6608、6607、6605、6603、6600、6599) で失敗するが、この issue の変更は依存を変えない。それ以外 (gofmt、goimports、`backend:lint`、`backend:test`、prettier、`frontend:lint` (警告 9 件は既存)、`frontend:test`) は通った。
