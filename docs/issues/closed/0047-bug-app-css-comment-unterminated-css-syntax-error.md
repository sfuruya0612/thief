# app.css のコメント内 `*/` によりビルド時に CSS 構文エラー警告が出る

Created: 2026-07-18
Completed: 2026-07-19
Model: Claude Sonnet 5

## 症状

`mise run frontend:build` (`vite build`) の実行時、CSS minify 中に次の警告が出力される。

```
warnings when minifying css:
▲ [WARNING] Unexpected "*" [css-syntax-error]

    <stdin>:3227:7:
      3227 │ --line-*/--text-*) を使い light/dark 両対応。
           ╵        ^
```

ビルド自体は警告のみで失敗しないが、コメントが途中で終端されており、以降の CSS の解釈が意図通りになっているか保証されない。

## 再現手順

1. `mise run frontend:build` を実行する。
2. コンソール出力に上記の `css-syntax-error` 警告が出ることを確認する。

## 原因

`frontend/src/app.css:3006-3011` のコメントブロックに原因がある。

```css
/* ============================================================
   ログビューア (CloudWatch Logs / Cloud Logging)
   デザイン Turn 8/9。テーマ変数 (--bg-*/
--line-*/--text-*) を使い light/dark 両対応。
   severity 色 (err/warn/info) のみ両テーマ共通の固定色を使う。
   ============================================================ */
```

3008 行目の `--bg-*/` に含まれる `*/` が CSS コメント終端 (`*/`) として解釈され、コメントが `--bg-*` の直後で終了してしまう。
続く `--line-*/--text-*) を使い light/dark 両対応。` 以降がコメント外の CSS コードとして解釈されようとし、`*` を含む不正な構文として minifier が警告を出す (3011 行目の `============================================================ */` の `*/` が今度は対応しないコメント終端として扱われ、そこから次のルール `.lv-root { ... }` までの間の文字列がどう解釈されているかは minifier の復旧ロジック依存で保証されない)。

## 根拠

`git blame` により、該当コメントはコミット `74ba3c0d` (2026-07-18) で追加されたことを確認した。
`mise run frontend:build` の実行で警告が再現することを確認済み。
`mise run frontend:lint` (`eslint` + `tsc --noEmit`) はこの種の CSS 構文を検査しないため、lint では検出されない。

## 対応方針

コメント内でテーマ変数名を列挙する際、`*/` という 2 文字の並びを作らない表記に変える。
例: `--bg-*` の後にスペースを入れる (`--bg-* /`) か、変数名を `、` で区切って改行をまたがせない (`--bg-*、--line-*、--text-*`) 。
CSS コメントは入れ子にできないため、今後同様のワイルドカード変数名の列挙をコメントに書く際は `*/` の並びが生じないか確認する必要がある。

## 解決方法

`frontend/src/app.css:3008-3009` の該当コメントを、対応方針で挙げた読点区切りの表記に修正した。

```css
/* ============================================================
   ログビューア (CloudWatch Logs / Cloud Logging)
   デザイン Turn 8/9。テーマ変数 (--bg-*、--line-*、--text-*) を使い light/dark 両対応。
   severity 色 (err/warn/info) のみ両テーマ共通の固定色を使う。
   ============================================================ */
```

改行をまたいでいた `--bg-*/` → `--line-*/--text-*` の並びを 1 行にまとめ、区切りをスラッシュから
読点に変えたことで `*/` という 2 文字の並びが生じなくなった。

### 実施した検証

- `grep -n '\-\*/' frontend/src/app.css` で、同様の `*/` を含むワイルドカード変数名の列挙が
  他に残っていないことを確認した (該当なし)。
- `mise run frontend:build` を実行し、`css-syntax-error` 警告が出力されないことを確認した
  (残る警告はバンドルサイズに関する既存の無関係な警告のみ)。
- `mise run check` (backend/frontend の fmt + lint + test) が全て通過することを確認した。
